# Reorienting

You may be told to "reorient" when your session has been idle for some time and the environment has changed in 
some significant way. To reorient, run these substeps:

1. [Rebase](rebase.md) any worktrees you are working on. This involves checking intermediate commits for salient 
changes. These changes might include changes that make your work moot, or require significant rearchitecting; look 
for such changes carefully.

2. Reconsider the approach to your original brief. Did the environment change in ways that make the original 
approach inappropriate? What needs to be rearchitected? Rebuild whatever you think needs updating. If the initial 
brief is now wrong, moot, or inappropriate, evaluate the right path forward, and brief the user (jump to the last 
step below).

3. If approproate, finish the project to complete the initial brief.

4. If appropriate, transition to the [end-of-work rules](end-of-work-rules.md), including squashing and giving the 
user the synopsis of the work.
